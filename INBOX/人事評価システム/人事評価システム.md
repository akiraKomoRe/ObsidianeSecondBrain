# 人事評価システム

昭和建設工業向けの人事評価Webアプリ（Next.js）。日報・週報からAIで週次評価を作り、期首目標→期末評価（本人・上長・部長）までを回す。

- 評価データはまだ未入力（本番データなし）
- 詳しい仕様は [[システム/README|README]]

## フォルダ構成

| 場所 | 中身 |
| --- | --- |
| `システム/` | アプリ本体（ソースコード・設定・Supabase定義）。ここで `npm` コマンドを打つ |
| `システム/README.md` | 仕様・セットアップ手順の詳細 |
| `システム/supabase/` | DBのテーブル定義（migrations）と初期データSQL |
| `データ/初期データ.json` | デモ用の初期データ（社員5名・部署・評価期間・評価項目など）を書き出したもの |

## ローカルで動かす

```bash
cd INBOX/人事評価システム/システム
npm install
npm run dev
```

ブラウザで http://localhost:3000 を開く。`.env.local` を置かなければ **ローカルモード**（データベース・APIキー不要）で動く。

- 入力したデータは `システム/.data/db.json` に保存される（Gitには入らない）
- 初期状態に戻したいときは `システム/.data` を消す
- 本番（Supabase + Claude API）につなぐときは `システム/.env.example` を `.env.local` にコピーして値を入れる

## 注意

- **OneDrive上に置く場合**：`npm install` すると数万ファイルの `node_modules` が同期されて重くなる。開発するときは OneDrive の外（例：`C:\dev\人事評価システム`）に `システム` フォルダをコピーして動かすのがおすすめ。OneDrive側は保管用にする
- **Obsidianが重くなる場合**：設定 → ファイルとリンク → 「除外するファイル」に `node_modules`、`.next`、`.data` を追加する
- **Vercelで公開する場合**：プロジェクト設定の Root Directory を `INBOX/人事評価システム/システム` に変更する
- GitHub ActionsのCIは `INBOX/人事評価システム/システム` で実行するように設定済み
